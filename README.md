# Akana (Turkish NLP Toolkit)

[![PyPI Version](https://img.shields.io/pypi/v/akana.svg)](https://pypi.org/project/akana/)
[![License: MIT / Apache-2.0](https://img.shields.io/badge/license-MIT%20%2F%20Apache--2.0-blue.svg)](LICENSE-MIT)
[![Rust: >= 1.75](https://img.shields.io/badge/rust-%3E%3D1.75-orange.svg)](https://www.rust-lang.org)
[![Python: >= 3.10](https://img.shields.io/badge/python-%3E%3D3.10-blue.svg)](https://www.python.org)

**Akana** (named after *Ak Ana*, the primordial creator goddess in Turkic mythology) is a modern, blazingly fast Turkish Natural Language Processing toolkit written in **Rust** with seamless **Python bindings via PyO3** and native hardware SIMD acceleration via **StringZilla**.

Repository: [https://github.com/altaidevorg/akana](https://github.com/altaidevorg/akana)

---

## Key Features

- **Phonology & Orthography Engine**:
  - Turkish alphabet characteristics and locale-aware casing (`ı` $\leftrightarrow$ `I`, `i` $\leftrightarrow$ `İ`).
  - Major (2-way `A/E`) and Minor (4-way `I/İ/U/Ü`) Vowel Harmony validation.
  - Consonant softening / mutation ($p \rightarrow b$, $ç \rightarrow c$, $t \rightarrow d$, $k \rightarrow \check{g}/g$).
  - Epenthetic vowel drop (*burun* $\rightarrow$ *burnu*, *akıl* $\rightarrow$ *aklı*).
  - Consonant doubling / gemination (*hak* $\rightarrow$ *hakkı*, *his* $\rightarrow$ *hissi*).
- **Tokenization & Sentence Segmentation**:
  - Zero-allocation, rule-based Turkish tokenizer handling proper nouns with apostrophes (`İstanbul'da`), abbreviations (`Prof.`, `Dr.`, `vb.`), currencies, URLs, emails, hashtags, dates, and times.
  - Sentence Boundary Detector with Turkish quotation and abbreviation lookahead.
- **Normalization & Spell Checking**:
  - **Asciifier** & **De-asciifier** for Turkish diacritics restoration.
  - **SIMD Spell Checker**: Accelerated with **StringZilla** hardware instructions for ultra-fast Levenshtein / edit distance candidate scoring.
  - **Informal Text Normalizer**: Spoken Turkish colloquialisms reduction (`yapcam` $\rightarrow$ `yapacağım`, `geliyom` $\rightarrow$ `geliyorum`, `noldu` $\rightarrow$ `ne oldu`) and letter elongation deduping (`çooook` $\rightarrow$ `çok`).
- **Dual-Engine Morphology Suite**:
  1. **Standard Morphology (`akana.Morphology`)**:
     - **66,436-Item Root Lexicon**: Zemberek's default dictionaries (TDK master dictionary, non-TDK words, proper nouns, person names and abbreviations), generated by `scripts/build_full_lexicon.py` with Zemberek's own POS and attribute rules, pronunciations and compound data, plus akana's supplements (`scripts/lexicon/akana-legal.dict`: HMK, TBK, AİHM, *tebliğname*, ...; given names and surnames of akana's PII lists that Zemberek lacks, `akana-names.dict`; misspellings read as nonstandard with the TDK lemma, `akana-spelling.dict`).
     - A port of Zemberek's morphotactics: 287 states and 989 suffix transitions with morphophonemic templates and conditions, and stem alternations generated at load time (*kitab-ı*, *redd-i*, *burn-u*), so misspellings such as *kitapda*, *gelti* or *kitapı* get no analysis.
     - Numbers, Roman numerals and abbreviations take the suffixes of their spoken form (`1923'te`, `%50'si`, `15.`, `XIX.`, `İİK'nın`, `TBMM'de`).
     - Analyses are ranked by a corpus frequency prior estimated on court decisions mixed with the sentences of the UD Turkish treebanks, whose part-of-speech tags also split the words read in more than one part of speech (`kararının` is *karar+P3sg+Gen*, `hakkı` the noun *hak*, `Ali` the name).
     - **Compound Word Decomposer**: compounds the lexicon marks or productive patterns on lexicon roots (`denizaltı` $\rightarrow$ `deniz + altı`, `başbakanlar` $\rightarrow$ `baş + bakanlar`); *mahkeme* is not *mah + keme*.
     - Morphological Generator on the same graph (`generate("kitap", ["Noun", "A3sg", "P1sg", "Dat"])` $\rightarrow$ `"kitabıma"`); a generated word always analyses back to the requested tags.
     - Context-aware Disambiguator: the corpus prior plus bounded context rules (genitive–possessive agreement, postposition case, light verbs, determiners).
  2. **Syntactic Expressive Morphology (`akana.SyntacticMorphology`)** *(Google FSMNLP 2019 format)*:
     - **Inflectional Groups (IG)**: the standard analyzer's readings, split where Zemberek's morphotactics derive (participles, converbs, verbal nouns, voice, *-Abil*, *-lIk*, *-lI*, *-sIz*, *-ki*, the copula), each group with its POS and Universal Dependencies features as UD Turkish writes them (`Case`, `Number`, `Person`, `Number[psor]`, `Person[psor]`, `Tense`, `Aspect`, `Evident`, `Mood=GenPot`, `Polarity`, `Voice`, `VerbForm`).
     - **Zero-Derivation Elimination**: the lexicon lists cross-categorized roots (*güzel* as adjective, adverb and noun), and an adjective inflected as a noun (*güzeller*) is a noun; only the copula (*evde-yim*, *güzel-di*) opens a group of its own.
     - Same lexicon, ranking and coverage as the standard analyzer.
- **Modern & Classic Turkish Readability Suite**:
  - **Kalyoncu (2025) Formula Suite**: Multi-regression equations (Formulas 1–4, $R^2$ up to 0.99) with embedded 4,600-word familiarity lexicon and exact grade-level mapping (*3. Sınıf Öncesi* to *Lisansüstü*).
  - **Classical Formulas**: Ateşman (1997), Çetinkaya-Uzun (2010), and Bezirci-Yılmaz (2010).
- **Turkish AI Writing Style Auditor & Humanizer Engine**:
  - Detects LLM writing signatures: punctuation anomalies (excessive em-dashes, semicolons with conjunctions, colons), predicate tense repetition (`-mektedir` ratio), rhythm monotony ($CV = \sigma / \mu$), bureaucratic connectors, translationese calques, tricolon lists, and hypophora questions.
  - Actionable prompt generation across 5 registers (*hukuki-idari, akademik-kurumsal, analitik-gazetecilik, deneme-blog, edebi-yaratıcı*).
  - Trained AI-text detector in every audit report (`report.ai_detection`, next to the rule-based `ai_score`, which counts style findings): calibrated probability that the text is AI-written, from 500 gradient-boosted trees over 75 signals (content statistics, mined AI phrases such as *"Elbette"*, *"önemli bir rol oynar"*, token-transition scores over Akana's own embedding tokenizer), with a Turkish "why AI" report. On a held-out OpenAI evaluation set it flags about 95 of 100 AI texts long enough to judge (65+ words), at 1% false alarms on separate human texts. Not proof of authorship; poems get no decision, academic text a warning, shorter or highly repetitive texts are not judged.
  - For texts the detector judges AI, `humanize_prompt` starts with the signals that made the text look AI.
- **Syntax & Universal Dependencies**:
  - Rule-based dependency parser with Universal Dependencies relations and CoNLL-U output. On the UD Turkish test splits it attaches 55.9 % of words to the right head (UAS) and 41.9 % with the right relation too (LAS), where attaching every word to the next word that is not punctuation gets 51.8 % UAS (`scripts/parser_ud_eval.py`): a margin of four points, and on Atis (42.8 against 51.3) none. Trained parsers do much better: use it for rough structure.
- **High-Level NLP Primitives**:
  - Turkish Syllabification & Hyphenation.
  - Number to Words Converter (Cardinals, Ordinals, Currency).
  - Named Entity Recognition (PER, LOC, ORG, DATE, MONEY, PERCENT).
  - Keyword Extraction (Turkish RAKE) & Extractive Summarization (TextRank).
- **Turkish Text Chunking Suite for RAG & LLMs (Chonkie-Inspired)**:
  - **`SemanticChunker`**: Segments long Turkish documents at natural topic shifts using embedded 2-bit TurboQuant vector similarity drops.
  - **Adaptive Threshold Modes**: Direct `similarity`, `percentile` (default: 0.75), `standard_deviation` ($\mu - k\sigma$), `interquartile` ($Q_1 - k \cdot IQR$), and `auto`.
  - **Similarity Smoothing**: Built-in 5-point Savitzky-Golay and Moving Average digital filters to suppress high-frequency local noise in sentence transitions.
  - **`SDPMChunker` (Semantic Double-Pass Merge)**: Two-pass hierarchical merge algorithm creating dense, coherent chunks with high information packing for vector databases.
  - **`SentenceChunker`**: Rule-based sentence chunking respecting Turkish grammatical boundaries with configurable token counts and overlaps.
  - **High Performance**: **>50,000–1,000,000 words/sec** on CPU with exact UTF-8 character and byte offset preservation.
- **Embedded Turkish Sentence Embeddings (TurboQuant 2-Bit Model2Vec)**:
  - **Ultra-lightweight (2.5 MB)**: Built-in 2-bit quantized static sentence embedding model distilled from BGE-M3 (`altaidevorg/turkish-bge-m3-model2vec-turboquant-2bit`).
  - **256-dimensional** vector embeddings with **92.19%** STSb-TR benchmark accuracy.
  - **High Throughput**: **>20,000 sentences/sec** on CPU with zero deep learning runtime or PyTorch dependencies.
  - Built-in cosine similarity and batch embedding support.
- **Grammatical Error Detection & Correction (GED/GEC)**:
  - **Rule-based and precision first**: 33 rules in 17 error categories: clitics (`de/da`, `ki`, `mi`), consonant assimilation (*kitapda* $\rightarrow$ *kitapta*), vowel drop (*şehire* $\rightarrow$ *şehre*), over-narrowing (*başlıyan* $\rightarrow$ *başlayan*), number and proper-noun apostrophes (*1923'de* $\rightarrow$ *1923'te*, *Ankara'lı* $\rightarrow$ *Ankaralı*), split *-ebil* (*ola bilir* $\rightarrow$ *olabilir*), indefinite determiners (*bir çok* $\rightarrow$ *birçok*), reduplications (*elele* $\rightarrow$ *el ele*) and more. 26 rules are on by default: the ones that leave correct, edited Turkish alone. The other 7 are experimental and run only when asked for. It does not cover all 25 GECTurk error types (see the [benchmark](#grammar-checker-precision-and-recall-gecturk-court-decisions-wikipedia)).
  - **Selectable rules**: every rule has a stable id (`de-da-after-verb`, `mi-merged`, ...); choose them per checker or per call (`rules=`, `enable=`, `disable=`, `experimental=True` in Python; `RuleSet` in Rust; `--rules/--enable/--disable/--experimental` in the CLI). `akana.grammar_rules()` and `akana grammar --list-rules` list them.
  - **Diagnostics**: Turkish and English explanations, character offsets, the rule id, and the rule's measured precision as `confidence`.
- **Turkish PII Masking & Bi-Directional Restoration (KVKK-Aligned)**:
  - **50+ Turkish PII Categories**: Comprehensive recognition of personal identity identifiers: TCKN (Turkish Republic ID with Modulo-10/11 algorithmic validation), VKN (Tax ID), IBAN (MOD-97 checksum; IBAN, TCKN and VKN shapes after their trigger words are masked even when the checksum fails), Credit Card (Luhn check), Turkish and international person names and surnames (curated lists plus 4,592 given names from Zemberek; names that are also words, such as *Deniz* or *Metin*, need a title, a role, a surname or a capital in mid-sentence), GSM and landline phones, Addresses, Passports, Driving Licenses, Vehicle Plates, VIN, IMEI, MAC, IP Addresses, Port numbers, Age/Age ranges, Blood types, Health conditions, Passwords, API tokens (OpenAI, Anthropic `sk-ant`, GitLab `glpat-`, GitHub PAT, HuggingFace `hf_`, Groq `gsk_`, npm `npm_`, Stripe, SendGrid, JWT, Bearer, PEM, Webhooks, Database URLs), and OTP codes.
  - **Positive Private Date & URL Detection**: Accurately isolates private personal dates (birth dates, appointment schedules, billing due dates) without false positives on calendar holidays or campaign end dates. Recognizes private URLs containing sensitive authentication and session tokens.
  - **Bi-Directional Restoration with Morphological Vowel Harmony**: Automatically tracks an in-memory or serializable mapping dictionary to restore masked entities losslessly, adapting case and possessive suffixes in downstream text according to Turkish 2-way and 4-way vowel harmony (e.g. `{{AD_1}}'a` $\rightarrow$ `Ahmet Yılmaz'a`, `{{AD_1}}'e` $\rightarrow$ `Mehmet Demir'e`). Supports conversational session continuity via `mask_with_vault` to persist identifiers across multi-turn dialogues.
  - **Multiple Masking Modes**:
    - `placeholder`: Standard structured tokens (`{{AD_1}}`, `{{TCKN_1}}`, `{{IBAN_1}}`) designed for clean downstream processing and 100% reversible restoration.
    - `surrogate`: Statistically and morphologically valid Turkish synthetic replacements (e.g., valid surrogate TCKNs, realistic Turkish names, valid surrogate IBANs).
    - `tag`: Standard semantic entity tags (`[AD]`, `[TCKN]`, `[IBAN]`).
    - `anonymize`: Category label redaction replacing sensitive data with uppercase entity tags (`[AD]`, `[TCKN]`, `[SIFRE]`, `[IBAN]`).
  - **Smart Non-PII Filtering**: Preserves corporate/functional emails (`info@`, `destek@`, `satis@`) and public dates while filtering individual personal data. Optionally keeps the names of well-known public figures (`preserve_public_figures=True`: *Atatürk*, *Nazım Hikmet*, *Fatih Sultan Mehmet*), only when the whole name is such a phrase.
  - **Informal Addresses**: Abbreviated, lower-case and all-caps addresses as people type them (*sedefli mh bayır sk. bina 89 D: 22*), with the district and province around them.
  - **Optional Model2Vec Context Scoring** (`use_embeddings=True`): Akana's built-in 256-dim Turkish embeddings decide ambiguous names with no other evidence, and find health conditions missing from the dictionary before a clinical trigger (*fibromiyalji tanısı*, not *futbol hastasıyım*). `scripts/experiment_pii_embeddings.py` measures where this helps and where trigger words do better.
  - **High Performance**: **>4,500 docs/sec** on short messages (about 0.2 ms per 90-character document) on one CPU core.
- **High-Performance Architecture**:
  - Pure Rust core with zero JVM dependency.
  - Python package via `pyo3` and `maturin` (compatible with `uv`).
  - Command Line Interface (CLI) for shell workflows.

### Morphological Analysis on Held-Out Treebanks (`scripts/ud_eval.py`)

The analyzer and the disambiguator on UD Turkish data that trains nothing akana ships: the test
splits of the six treebanks whose train and dev sentences feed the ranking prior, and all of
IMST (CC BY-NC-SA, used for evaluation only). BOUN's test split is broken down by genre.
*Coverage*: the word has a reading. *Class*: the disambiguated reading's part of speech is UD's
(a participle or verbal noun counts as a verb or as the class it derives; names, punctuation
and symbols left out). *Twins*: the same, on the words whose readings fall in two classes or
more, one of them UD's. *Lemma*: the reading's lemma or root equals UD's lemma; UD writes a
verb's stem and some derivations differently, so this is agreement, not accuracy.

### Grammar Checker Precision and Recall (GECTurk, court decisions, Wikipedia)

A grammar checker that rewrites correct text does more harm than good, so each rule is measured on **correct, edited Turkish** as well as on errors:

- **Clean text**: 7,500 sentences from Turkish court decisions (CC0; 1,500 of them are committed as `crates/akana-core/tests/data/grammar_clean_court.txt`) and 4,452 Wikipedia sentences from the RagTurk articles (measured locally, not redistributed).
- **Errors**: the GGLab/GECTurk test set (20,769 sentences, 25 synthetic error types) and its 300 human-written movie-review sentences. A finding counts as right when it overlaps a token GECTurk labels as an error.

A rule is **on by default** only if it raises a false alarm on at most 1 in 1,000 clean sentences and, where GECTurk has its error type, at least 80 % of its GECTurk findings are on a labelled error. GECTurk labels only the errors it injected. For a rule whose errors it does not inject, such as proper-noun apostrophes or *peşpeşe*, every finding in the measured text was read and judged. The other rules are **experimental**: off unless asked for. `cargo test -p akana-core` runs the default rules over the committed clean sentences (`tests/grammar_precision_gate.rs`) and fails if any rule fires on more than 1 in 1,000 of them, or if `correct` changes more than 3.

The GECTurk paper's neural models are scored with its own correction metric, not comparable to these numbers.

### Ultra-Low-Memory Turkish RAG Retrieval Benchmark (RagTurk & Turkuaz-RAG)

Evaluated on **`metunlp/ragturk`** (Turkish agglutinative morphology failure modes, [arXiv:2602.03652](https://arxiv.org/abs/2602.03652); first 300 articles of `formal_5k`: 2,732 chunks, 600 questions) and **`eneSadi/turkuaz-rag`** (multi-context QA; first 500 samples: 1,000 news texts, 500 questions) with compiled **USearch** (`unum-cloud/usearch`) metrics. > **Reproducibility:** `python scripts/benchmark_rag_real_data.py --dataset all --readme` prints this table (defaults: 300 RagTurk articles, 500 Turkuaz samples; Turkuaz is streamed once and then read from `.cache/rag_benchmarks/turkuaz.jsonl`, so later runs work offline). Every quality figure is deterministic: two runs give the same reciprocal rank for every question. See also the runnable workflows in [`examples/11_ultra_low_memory_retrieval_usearch.py`](examples/11_ultra_low_memory_retrieval_usearch.py).

> **Correction (0.8.0):** earlier versions of this table (and of the benchmark script, example and README snippets) built USearch indexes as `Index(ndim=nbytes, dtype="u8")` and added numpy `uint8` arrays. USearch reads `uint8` arrays as packed bits and unpacks them into such an index, so it kept only the first `nbytes` bits of each vector as 0/1 bytes: 1/8 of each dense vector, and none of the hybrid's sparse half. Every USearch row of the old table measured that loss (for example 36.7% RagTurk Recall@10 for the hybrid, and 1-bit appearing better than 2-bit). Indexes must store the packed bytes verbatim: `Index(ndim=8 * nbytes, dtype="b1", metric=...)`, which also passes `nbytes` to the compiled metric. Any index built the old way has to be rebuilt. After `Index.load()` or `Index.view()`, set `index.metric` to the compiled metric again: USearch restores the metric from the file header, which cannot hold a function pointer (a reloaded `b1` index crashes on search without it; a reloaded `u8` index silently used USearch's own cosine).

#### Key Empirical Findings

1. **2-bit TurboQuant keeps almost all of FP32's quality**: 0.738 vs 0.772 MRR@10 on RagTurk and 0.375 vs 0.383 on Turkuaz, at 1/16 of the memory. **1-bit** halves the memory again and costs another 0.05–0.08 MRR@10.
2. **Morphological BM25 is the strongest single retriever on both sets** (0.880 MRR@10 on RagTurk, 0.473 on Turkuaz; RagTurk questions share most of their vocabulary with their passages). Fusing it with 2-bit dense through RRF matches its RagTurk Recall@10 (97.8% vs 98.0%) but not its MRR@10 (0.837), and trails it on Turkuaz.
3. **The 128-byte single-buffer hybrid is one memory-mappable index with no inverted index.** It adds +0.05 (RagTurk) and +0.07 (Turkuaz) MRR@10 over 2-bit dense alone but stays below BM25: its sparse half holds the 16 heaviest terms of a passage (a RagTurk chunk has a median of 39 terms), weighted by repetition and part of speech. Function words are no terms (`ve`, `için`, `bu`, `bir`, `tarafından`), and only the twenty lemmas most frequent in both court decisions and general text (*almak*, *vermek*, *yer* ...) carry an IDF weight, because a full static IDF cost the hybrid 0.01–0.04 MRR@10 by trading a passage's repeated topic words for words it mentions once.
4. **Hybrid vectors depend on the morphology build.** 0.9.0's analyzer and sparse encoder change every `sparse_embed` vector and the sparse half of every hybrid vector built with 0.8.0 (dense halves are unchanged): rebuild such indexes. From 0.9.0 on, store `akana.encoder_info()` with an index and check it with `akana.check_encoder()` when you open it (see *Index compatibility* below); a release that changes vectors within the same sparse spec reports how many and keeps a stale index within 0.005 MRR@10 of a rebuilt one.
5. **Embedding cost:** on one core of a laptop CPU, the 128-byte hybrid embeds 170–240 court-decision chunks of about 214 words per second, the sparse half alone 200–220 and the dense half alone 1,600–2,100 (`scripts/benchmark_embedding_cost.py`, three runs; the machine's load moves these by a third). `embed_batch_hybrid` splits a batch of 512 or more texts across the CPU cores.

#### Index compatibility

An index stores what built it, and checks it when it is opened:

```python
import akana

info = akana.encoder_info()   # save this dict next to the index when you build it
# {'akana_version': '0.9.0', 'unicode_version': ..., 'sparse_spec': '1.0', 'hybrid_layout': 1,
#  'dense_model': ..., 'analysis_version': '1.0', 'analysis_fingerprint': ...,
#  'sparse_fingerprint': ..., 'dense_fingerprint': ..., 'fingerprint': ..., 'resources': {...}}

status = akana.check_encoder(stored_info, "hybrid")   # when you open it: the dict, or its JSON text
```

The second argument is what the index holds: `"sparse"` (`sparse_embed` vectors, or a BM25 index of their terms), `"dense"` (`embed` and the packed 2-bit and 1-bit vectors) or `"hybrid"` (the default). Each is judged by what its vectors depend on, so a new dense model asks dense and hybrid indexes to rebuild but leaves sparse ones alone.

- `"identical"`: this library was built from the same inputs as that kind of vector needs (the resources, the source of its encoders, akana's own `Cargo.lock`, the Unicode version) and produces exactly the vectors the index holds.
- `"compatible"`: the same sparse spec major (sparse vectors), the same dense model, tokenizer and weights (dense vectors), both and the hybrid layout (hybrid vectors). Some vectors differ, as code or a dependency changed: releases that change them say how many, and keep at most 5 % of documents' vectors changed and a stale index's MRR@10 within 0.005 of a rebuilt one, so no rebuild is needed.
- `"rebuild"`: term ids, term definitions, the dense model or the vector layout changed, or the stored record is not one `encoder_info()` wrote. Re-embed the documents.

An index built with 0.8.0 or earlier stores no encoder info and must be rebuilt; `CHANGELOG.md`
lists what else changed since 0.8.0 and how to migrate.

`Cargo.lock` and `rust-toolchain.toml` pin what the vectors depend on (the Unicode tables of the Rust standard library included), and ranking inside the analyzer and disambiguator is done in integers. The published wheels, and the sdist built into a wheel, are built with that toolchain and lock file and tested against the golden vectors on Linux, macOS and Windows before release. The fingerprints also cover the Unicode version and a probe set's vectors, so a build with another toolchain reports another fingerprint when either differs; a build without akana's own lock file (from crates.io, or as another project's dependency, whose resolved versions it cannot see) always reports one of its own: `check_encoder` then says `"compatible"`, not `"identical"`.

The hybrid metric's alpha (`set_hybrid_metric_alpha`, `get_usearch_metric_pointer_hybrid(alpha)`) is one value for the whole process: setting it changes the metric of every open index that uses it. It must be a number in [0, 1] (outside it is clamped; NaN raises `ValueError`).

```python
)

# A. SemanticChunker: Splits at natural topic shifts using TurboQuant embeddings
semantic_chunker = akana.SemanticChunker(
    chunk_size=512,
    threshold_mode="percentile",  # "percentile", "similarity", "stdev", "iqr", "auto"
    threshold_value=0.75,
    min_chunk_size=20,
    min_sentences_per_chunk=1,
    use_smoothing=True,
)
chunks = semantic_chunker(
    "Kuantum mekaniği atom altı parçacıkları inceler... "
    "Fenerbahçe dün akşam derbide galip geldi... "
    "Geleneksel Türk mutfağında baklava çok meşhurdur..."
)
for chunk in chunks:
    print(f"Chunk ({chunk.token_count} tokens, chars {chunk.start_index}:{chunk.end_index}): {chunk.text}")
    print("Sentences:", chunk.sentences)

# B. SentenceChunker: Fast sentence packing with token constraints and overlaps
sentence_chunker = akana.SentenceChunker(chunk_size=256, chunk_overlap=30)
sentence_chunks = sentence_chunker("Metin 1... Metin 2...")

# C. SDPMChunker: Semantic Double-Pass Merge for dense, cohesive chunks
sdpm_chunker = akana.SDPMChunker(
    chunk_size=512,
    threshold_mode="percentile",
    threshold_value=0.75,
    merge_threshold=0.65,
)
sdpm_chunks = sdpm_chunker("Uzun doküman...")

# D. Dict / JSON serialization
chunk_dict = chunks[0].to_dict()
print(chunk_dict["text"], chunk_dict["start_index"], chunk_dict["end_index"])

# 13. Turkish PII Masking & Bi-Directional Restoration (KVKK-Aligned)
raw_text = (
    "Müşterimiz Ahmet Yılmaz, 10000000146 nolu TCKN ve TR33 0006 1005 1978 6457 8413 26 "
    "nolu IBAN ile 12.05.1988 doğumludur. Şifresi: Limon004_."
)

# A. Reversible Structured Placeholder Masking
masked = akana.pii_mask(raw_text, mode="placeholder")
print("Masked:", masked["masked_text"])
# -> "Müşterimiz {{AD_1}}, {{TCKN_1}} nolu TCKN ve {{IBAN_1}} nolu IBAN ile {{DOGUM_TARIHI_1}} doğumludur. Şifresi: {{SIFRE_1}}."
print("Mapping:", masked["mapping"])

# B. Lossless Restoration with Turkish Vowel Harmony
restored = akana.pii_restore(masked["masked_text"], masked["mapping"])
assert restored == raw_text

# Downstream inflected text restoration (vowel harmony preserved automatically):
inflected_text = "Ödeme {{AD_1}}'a yapılmış ve {{AD_1}}'ın dosyası onaylanmıştır."
print(akana.pii_restore(inflected_text, masked["mapping"]))
# -> "Ödeme Ahmet Yılmaz'a yapılmış ve Ahmet Yılmaz'ın dosyası onaylanmıştır."

# C. Realistic Turkish Synthetic Surrogates Mode
surrogate = akana.pii_mask(raw_text, mode="surrogate")
print("Surrogate:", surrogate["masked_text"])
# -> "Müşterimiz Can Demir, 52381940562 nolu TCKN ve TR92 0006 1000 ... doğumludur..."

# D. Keep the names of well-known public figures, mask everyone else
engine = akana.TurkishPiiEngine(preserve_public_figures=True)
print(engine.mask("Nazım Hikmet'i en çok Ahmet Yılmaz okurdu.")["masked_text"])
# -> "Nazım Hikmet'i en çok {{AD_1}} okurdu."
```

### Offsets, threads and errors

- **Offsets are character offsets.** `text[start:end]` is the span for named entities (`start`/`end`), grammar findings (`start_offset`/`end_offset`), style findings (`start`/`end`), PII entities and chunks (`start_index`/`end_index`).
- **Calls release the GIL**, so a thread pool (a FastAPI server, a `ThreadPoolExecutor` ingestion job) runs them in parallel. `embed_batch`, `embed_batch_hybrid` and the packed batch functions also split a batch of 512 or more texts across the CPU cores themselves.
- **Objects can be configured while threads use them.** `Morphology.load_dictionary_*`, `SpellChecker.add_word`, `GrammarChecker.enable_rule`/`disable_rule` and `TurkishPiiEngine.enable_type`/`disable_type` wait for the calls in progress on that object, and the calls after them see the change. A `PiiVault` that threads share serves one `mask` at a time.
- **Engines are built once per process.** The lexicon and the embedding weights are loaded on first use and shared by every object, so the module-level functions (`analyze`, `stem`, `audit_ai_style`, `chunk_*`, `pii_mask`, ...) and constructors are cheap to call repeatedly.
- **An internal error raises `RuntimeError`** (not PyO3's `PanicException`, which `except Exception` does not catch).

## CLI Usage

The `akana` CLI supports direct text arguments or reading from file via `-f, --file`:

```bash
# Turkish PII Masking & Restoration (KVKK-Aligned)
akana pii-mask "Ahmet Yılmaz 10000000146 nolu TCKN ile başvurdu." --mode placeholder
akana pii-mask "Ali Kaya Kadıköy şubesine geldi." --mode surrogate
akana pii-mask -f confidential.txt --mode placeholder --json
akana pii-restore "Ödeme {{AD_1}}'a yapıldı." --mapping mapping.json

# Grammar checking (default rules; --experimental, --rules, --enable, --disable to choose)
akana grammar "Ali de geldi, Veli te geldi."
akana grammar --correct -f article.txt
akana grammar --experimental --disable capitalization --json "Pazardan üç elmalar aldım."
akana grammar --list-rules

# AI style auditing
akana ai-audit "Bu bağlamda kritik bir rol oynamaktadır."
akana ai-audit -f article.txt

akana humanize-prompt "Bu doğrultuda hayati önem taşımaktadır." --register blog

# Syntactic morphological analysis (Google FSMNLP format)
akana syntactic-analyze "geldiğimizde"

# Standard morphological analysis
akana analyze "evlerimizde"

# Readability analysis
akana readability "Küçük çocuk bahçede neşeyle koşuyordu."

akana syllabify "bilgisayar"

# Universal Dependencies Parsing

akana chunk --strategy sentence --chunk-size 256 --overlap 30 -f document.txt
akana chunk --strategy sdpm --chunk-size 512 --json -f document.txt
```

## Rust Crate Usage (`akana-core`)

Add to `Cargo.toml`:
```toml
[dependencies]
akana-core = { version = "0.5", default-features = true }
```

```rust
use akana_core::chunking::{SemanticChunker, SentenceChunker, SDPMChunker, ThresholdMode};
use akana_core::grammar::{GrammarRule, RuleSet, TurkishGrammarChecker};
use akana_core::morphology::TurkishMorphology;
use akana_core::syntactic_morphology::TurkishSyntacticMorphology;
use akana_core::embeddings::TurkishEmbeddings;
use akana_core::pii::{TurkishPiiEngine, PiiMode};
use akana_core::phonology::to_turkish_lower;

fn main() {
    let lower = to_turkish_lower("İSTANBUL");
    println!("Lower: {}", lower);

    // 1. Semantic Chunking with TurboQuant Embeddings
    let chunker = SemanticChunker::new(512, ThresholdMode::Percentile(0.75));
    let chunks = chunker.chunk("Kuantum mekaniği... Fenerbahçe dün akşam...");
    for chunk in chunks {
        println!("Chunk ({} tokens, {}-{}): {}", chunk.token_count, chunk.start_index, chunk.end_index, chunk.text);
    }

    // 2. Turkish Sentence Embeddings (TurboQuant 2-Bit)
    let embeddings = TurkishEmbeddings::new();
    let vec = embeddings.embed("Türkiye'nin başkenti Ankara'dır.");
    println!("Embedding dim: {}", vec.len()); // 256
    let sim = embeddings.similarity("ev", "evler");
    println!("Similarity: {:.4}", sim); // 0.9130

    // 3. Grammatical Error Correction & Diagnostics (the default rules)
    let grammar_checker = TurkishGrammarChecker::new();
    let res = grammar_checker.check("Ali de geldi, Veli te geldi. Cumhuriyet 1923'de kuruldu.");
    println!("Corrected: {}", res.corrected);
    for f in &res.findings {
        println!("[{}] '{}' -> '{}' ({:.2})", f.rule, f.original_text, f.replacement, f.confidence);
    }
    // experimental rules on request, by id or all of them
    let all = RuleSet::default().with_experimental();
    println!("{}", grammar_checker.correct_with_rules("Pazardan üç elmalar aldık.", all));
    let mut only_clitics = TurkishGrammarChecker::with_rules(RuleSet::empty());
    only_clitics.enable_rule(GrammarRule::DeDaHardened);

    // 4. Standard Morphology
    let morph = TurkishMorphology::new();
    let parses = morph.analyze("kitabım");
    for p in parses {
        println!("{}", p.formatted);
    }

    // 5. Syntactic Expressive Morphology (Inflectional Groups)
    let syn_morph = TurkishSyntacticMorphology::new();
    let syn_parses = syn_morph.analyze("geldiğimizde");
    for p in syn_parses {
        println!("{}", p.formatted);
    }

    // 6. Turkish PII Masking & Bi-Directional Restoration (KVKK-Aligned)
    let pii_engine = TurkishPiiEngine::new();
    let pii_res = pii_engine.mask(
        "Ahmet Yılmaz 10000000146 nolu TCKN ile TR33 0006 1005 1978 6457 8413 26 nolu hesaptan işlem yaptı.",
        PiiMode::Placeholder,
    );
    println!("Masked: {}", pii_res.masked_text);

    // Lossless restoration with automatic vowel harmony adjustment
    let restored = pii_engine.restore_with_mapping(
        &format!("İşlem {}'a ait hesaba başarıyla yansıtıldı.", "{{AD_1}}"),
        &pii_res.mapping,
    );
    println!("Restored: {}", restored);
}
```
